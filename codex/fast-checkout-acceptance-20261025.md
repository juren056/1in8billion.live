# v1.28.1 支付入口提速验收（2026-10-25）

问题：购买点击后先下载完整导出字体、生成高清封面并序列化整本演示 PDF，然后才创建 Stripe Checkout；点击还重复查询支付健康状态。

改动：支付前只检查已保存快照、浏览器能力、支持的输出设置及文字覆盖。文字检查采用随实际字体生成的 171 段 cmap 覆盖表，SHA-256 测试绑定发布字体，不下载字体或生成文件。付款模块提前随购买 UI 加载；使用页面已取得的支付可用状态直接请求订单，服务端仍决定实际可否支付。完整生成只发生在预览/导出时。修复韩文零宽断词符在 PDF 字体校验及换行中的兼容问题。

保留：完成记录与本机回读检查、领取凭证写入并回读、服务端金额/环境校验、幂等重试、付款后签名权益验证、支持范围拦截。未修改真实支付密钥、订单数据库、定价与收费模式，也未提交真实扣款。

证据：新增 5 项测试，覆盖无资源下载的准备、无效设置/未完成人生、字体文件一致性/缺字、实际支付客户端在模拟接口下的创建/重试/凭证存储失败，以及 48 份九语言样本。48 份样本检查合计约 1.5 秒（本机观察，不是网络支付耗时承诺）。现有全套回归检查和导出相关 12 项复验完成，构建、资源预算和 226 页面 SEO 校验通过。最终远端 CI 再验证完整 127 项。

旧浏览器自动化脚本的字体调用预期同步更新，本轮没有运行那些脚本。真实支付接口仅做健康及资源检查，不提交实际扣款。发布结果另行补录。
