## 检查边界

真实 Chrome 隔离环境，390×844 手机尺寸模拟，默认以电影夜景主题检查。访问首页、出生弹窗、游戏工作台、国家统计、首页页脚、外观菜单、纪念包、比较页、日本国家页和快速玩法指南。四个抽查内页的已选按钮／表单目标未发现同类对比度问题，不代表整页所有文字或所有交互状态已通过。

故事条目的文字使用浏览器内临时测试夹具以稳定触发布局，不是改动线上资料或玩家存档。所有模拟访问阻断 GA/GTM/Clarity，不提交支付。证据为 `audit/night-ui-review-20261022/report.json` 及同目录截图。

此前验收没有覆盖完整的动态故事条目、样式失效和浮层互斥；后续必须将其加入固定回归。

## 第一批：共享主题与可读性

1. 把表格、故事条目、模型说明、选择按钮、表单、提示条的背景与前景成对定义在共享主题组件中，清理遗留硬编码浅色背景和白色按钮字。
2. 表格基础样式自身可安全跟随主题，核心可读性不依赖后续覆盖样式成功加载。覆盖正常、延迟和单个样式失败场景，控制首屏资源预算。
3. 动态插入及刷新后的内容使用同样规则，覆盖未选择、已选择、禁用、加载、提示和错误状态。
4. 保留电影夜景的深蓝与金色，只修正不合适的文字、背景、分隔线与层级。

验收：四主题正文、表格标签／数字与按钮文字至少 4.5:1；正常和异常加载均可读。禁用状态另按实际可辨识性检查，不误报为普通可交互控件。图表文字和实际渲染的透明／混合背景也要纳入。

## 第二批：悬浮栏的显示生命周期

1. 首页保留固定位置的“继续人生”；悬浮栏作为辅助入口。
2. 推荐仅在首页主操作不在视口、用户向上回滚时显示；向下阅读时收起。
3. 游戏中、任何对话框／菜单打开、输入时及进入页脚区域均隐藏；焦点在栏内时不突然隐藏。
4. 增加“收起”，本次访问记住选择，避免不断重新出现。未关闭时仍保留继续／重新出生的现有语义与确认流程。
5. 直接依据核心视图或激活视图判断页面状态，避免依赖可选增强模块的 CSS 类；主操作观察目标跟随继续／新人生状态，尺寸改变后刷新遮挡边界。

验收：首次访问、有存档、无效存档、已结束人生、待决策、取消重生、刷新、切换主题／语言、菜单／弹窗、软键盘、页脚、旋转屏幕，以及可选模块延迟／失败。不得遮住主操作、故事、购买按钮；两个底部栏不能同时争抢视口。

## 第三批：布局、语言与全流程回归

1. 手机统计表给指标和数值合理列宽；长数值、单位、缺失值和长翻译可读，不用缩小字体解决空间问题。
2. 统一中文单位和提示，保持年度、年月、统计数值、模拟规则和既有存档不变。
3. 检查外观菜单的定位、窄屏滚动、关闭、焦点恢复和与其他菜单互斥。菜单覆盖部分内容本身属于正常弹层行为，不能单凭截图把它判为故障。
4. 扫描所有静态页面模板及动态状态：首页、出生、游戏、决策／消费选择、结局、家族树、本机人生、批量模拟、比较、国家详情、指南、纪念包、订单与错误／恢复页面。

最终验收矩阵：四主题 × 九语言 × 手机／桌面；另加 320px 窄屏、200% 缩放、键盘焦点、触摸滚动及慢网／样式失败。先分别通过可读性和显示状态门槛，再运行完整模型／存档／SEO／支付回归；真实支付只检查结账交互，不提交扣款。部署后在正式域名复验同样的关键场景，并核对精确版本。
