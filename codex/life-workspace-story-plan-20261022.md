# 人生工作台、自动开始与故事质量改进计划

日期：2026-10-22。检查基线：正式站 v1.22.1 / e00c962。此文件是本轮检查与执行方案；没有修改生产代码、模拟规则或部署。

## 实查与证据

通过 CUA 实际打开 https://1in8b.app/zh-hans/ ，完成出生、8倍速、推进至两岁决定、选择“观察石头和小虫”；界面知识从50变为53，家人年龄同时更新。对手的资料／故事／家人三栏、按年分组及重要抉择暂停值得借鉴。其数据来源和在线人数等声明未独立验证，不作为本站产品事实或统计来源。另打开本站中文首页，发现部分英文恢复提示与示例国家／年数未本地化。未覆盖或删除浏览器已有存档。

### 已确认代码问题

1. app.js:790 使用 `countryData.wh` 触发战争事件，条件为 wh>0.1、每年 chance(wh*0.1)，只有五条事件文案；app.js:1372 第二处又用相同字段添加动乱事件。原始172条数据均存在wh，156条值大于1；中国wh=5.97、war=0，日本wh=6.06、war=0。中国第一处触发条件等价于每年59.7%概率。`wh`的原始来源／精确定义还需核验；可以确认该实现不能充当可信的冲突概率映射。`war`本身也有2.0等值，不能直接当0–1概率照搬。
2. app.js:3624 出生确认先startLife，随即queueMicrotask设置paused=true、停止计时并保存；rebirth-reveal.js提供首屏停读提示。这与本次“开始后自动运行”的需求相反。
3. app.js:1386 applyEventEffects通过中文事件文字关键词改变属性。英文事件走同一函数时存在效果不一致风险；需用相同事件条件做双语单元复现，再迁移为结构化效果，不能只翻译文字。
4. app.js:1306 generateYearlyEvent为年龄段小事件池；缺少事件ID、近期冷却和人物前置条件。战争池也没有父亲是否存在／已去世／是否已征召等约束；截图中同一事件多年重复与代码缺陷一致。
5. 国家统计的生活满意度读取c.ls并回退5.5，但当前172条原始记录均无ls字段。说明存在静默回退掩盖字段映射问题的风险，需纳入字段契约审计，不能直接认定wh就是ls而替换。

### 用户体验问题

- 角色基础资料、家庭、属性、家庭背景铺成全宽纵向块；看新事件时看不到状态变化，家庭信息存在重复展示。
- 年表把事件逐条平铺，缺少当年主线、人物关系、选择后果及后续回响；仅扩大文案池不解决逻辑问题。
- 截图中的人物17岁仍呈明显幼童外观，属于年龄阶段资源需要检查的迹象，尚未完成全资产核验。家庭人物年龄、称谓、存活状态也需建立统一状态来源，避免多个展示组件各算一套。
- 本站中文首页实查存在英文恢复提示、部分示例国家／年数、较机械的“促销”等翻译。上一轮主要验证可读性，没有充分覆盖内容逻辑；新验收必须补上。

## 第一阶段：纠正事件与开局（P0）

- 建立字段契约表：字段含义、量纲、空值和有效范围；审计所有概率消费者，特别是wh／war／ls。未核实字段不得作为当前现实冲突判断。明确war游戏输入的映射后修复两个入口，并对概率边界做检查。
- 出生卡最终“开始这段人生”后进入运行状态，按所选1秒／5秒节奏自然推进。保留暂停、真实待决策、手动逐年；继续旧存档时尊重已保存的暂停状态。不用“自动开始”偷偷替用户选择。
- 战争类事件增加人物与状态条件、冷却、唯一事件限制；不允许父亲已去世仍被征召、没有子女却出现子女毕业等矛盾。
- 引擎／事件规则版本隔离：新人生使用新规则；旧已完成人生、已购快照和旧回放不重写，旧种子继续走兼容规则。修复后重新生成新版首页样本及其验证材料，旧记录保留原版本标识。

验收：零冲突配置不触发战争事件；边界／缺失字段受控；出生确认后计时确实推进或进入合法抉择／结局；旧暂停存档不被自动推进；旧回放快照不变。

## 第二阶段：实时人生工作台（P1）

桌面目标：左260–300px角色卡｜中间弹性故事列｜右280–320px家庭／环境卡。宽度不足时先转双栏，再转手机单列；不能压缩正文硬塞三栏。

- 左：角色姓名／年龄／年月／地点、健康／幸福／知识／人际、收入／净资产、学历／职业；显示本次变化如“知识+3”，差值与实际状态同源，不能每次render都闪。
- 中：生活场景、播放控制、按年龄／年月分组的故事卡、当下抉择。普通年份与转折有层级，不强行每年安排灾难。阅读旧事件时暂停自动跟滚，出现“有新故事”入口。
- 右：父母／伴侣／子女动态状态、最近家庭变化、国家环境参考入口。移除重复家庭卡，人物点击可查看关系及相关事件。
- 两侧采用紧凑sticky布局，避免三列各自长滚动。详细图表、国家统计、模型说明仍保留在下方、默认展开，并提供跳转入口。
- 手机：顶部紧凑身份／年龄／关键数值摘要，故事优先；家庭与详细资料有明确入口。与待决策／购买栏互斥，不能再叠加常驻浮栏占满屏幕。
- 所有组件读取统一life状态，年龄／生死／关系／肖像阶段保持一致；保留四种主题，九种语言使用同一组件规范。

验收：320、390、768、1024、1440px及等效200%重排；变化反馈精确、不强制抢焦点；四主题对比度；所有原资料仍可访问；没有重复DOM ID和手机底栏遮挡。

## 第三阶段：有关系与后续的人生内容（P2）

先完成结构与一条端到端故事链，再扩展内容。第一版拟定160条以上有独立情境的事件模板，覆盖幼年／学龄／青年／成年／中年／晚年，以及家庭、朋友、学习、职业、健康、生活、迁移、晚年回顾；这是开发目标，不宣称已实现或有统计代表性。

事件结构：id、category、ageRange、eligibility、actorId、once／cooldown、effects、followUp、translationKey、rulesVersion。将“发生什么”“改变什么”“如何表达”分开。效果不得依据翻译后的句子猜测；普通叙述变化使用独立随机流或稳定派生值，避免多抽一句话就改变死亡／婚姻等结果。

- 场景依赖年龄、城乡、家庭资源、学业和职业等真实游戏状态；国家只作为情境条件之一，不用单一民族面孔或刻板印象替代个体差异。
- 一次性成长／毕业事件只发生一次；普通事件近期不连续重复；同类合理重复可以保留，但有不同人物／情境及后续。
- 示例故事链：结识朋友→一起学习或疏远→多年后再见；职业机会→接受培训或维持现状→之后出现工作回响。只在规则实际记录时显示因果，不凭空声称某选择造成某结局。
- 抉择明确取舍，处理选择后给即时结果与后续预期；重大选择暂停，普通日常轻反馈，避免每年弹窗。
- 九语言文案按事件ID管理，避免中文页面出现英文句子或把promotion翻成“促销”。高风险内容与新概率变更独立审查，不把新增故事量当成真实世界数据。

验收：每个事件可追溯到ID和条件；无非法人物／年龄／状态组合；同事件不违反冷却；同一事件效果与语言无关；旧引擎重放不漂移。固定种子覆盖所有172个国家，再对12个代表国家进行每国1000个种子质量抽查，分别报告死亡截尾后的事件密度、重复率、事件类别覆盖和故事链完成情况，不用“每人必有N件事”破坏早逝规则。

## 第四阶段：留存、纪念包价值与发布（P3）

- 漏斗：出生确认→首次推进→首个抉择展示／完成→首个故事链回响→合法结局→本人纪念包预览→结账→确认付款后导出。记录匿名事件类型及版本，不上传人物姓名、自由回忆、完整事件正文或支付信息。
- 先建立当前流量基线；优先观察开始到首次推进流失、抉择完成率、主动暂停阅读、故事回访、本人预览到结账。不能把高倍速挂机时长当作留存增长，也不承诺没有数据支持的转化提升。
- 纪念包展示本人已发生的关系与转折，形成“这是我的这段人生”的付费理由；在有值得保存的故事后自然提示，保留免费游玩，不持续打断故事兜售。
- 不复制对手文案／画面／未经核实的数据，不仿造在线人数、评价或玩家故事。SEO继续保持既有canonical、hreflang、sitemap和公开内容；不索引私人随机人生或订单。
- 每阶段分别通过规则、内容、交互与响应式门槛再推进；最终跑模型、存档、四主题九语言、样式失败、SEO、性能、支付授权／退款／交付回归。真实支付只验证到可交互结账，不提交扣款。
- Git发布后核对精确版本，正式域名复验开局、三栏／手机布局、代表故事链、旧存档／回放和购买入口，保存截图与验收回执。保留快速回滚路径。

## 推荐执行顺序

先字段误用／事件异常与自动开始，再实时资料工作台，再事件内容和关系链，最后增长与付费验证。上线开关分开控制布局和新规则，不能用视觉改版掩盖事件模型错误。


## 用户补充范围：全部事件的图片与互动（2026-10-22）

用户明确要求“全部”，本节覆盖范围优先于只做少量重点卡片的解释。所有人生事件都进入统一的图文互动卡系统，不保留一部分普通事件仍采用旧式纯文字条目的混合交付。图片和互动是全量要求；是否暂停与是否要求作出决定，仍按事件性质处理。

### 全量覆盖范围

出生、日常、成长、学业、朋友、家庭、恋爱、婚姻、育儿、职业、收入、迁移、健康、困境、退休、晚年及死亡／结局。覆盖当前故事流、事件详情、人生回顾、回放和旧存档记录的展示；家庭面板的事件入口指向同一张卡。纪念包中的事件选取与这些记录同源，不能虚构用户没有经历的内容。已购记录与旧模拟结果保持不变，旧数据通过展示适配器补充配图和详情，不伪造过去没有发生的选择或数值影响。

### 统一事件卡结构

- 年龄／年月、事件标题、场景图片、相关人物、简洁叙事、实际影响、互动入口。
- 所有事件有场景图片和可发现的互动入口。展开详情可查看人物关系、发生背景、已记录的属性变化、前后关联事件；支持收藏为关键时刻、加入本人纪念包的候选记忆。
- 已发生的普通事件以图文卡自然进入故事流；点击图片或“查看这一刻”打开沉浸详情。查看／收藏不消耗时间、不改变随机结果、不偷偷替用户选择。
- 所有待决策事件都使用插画弹出卡：时间与人物→情境叙述→2–4个有效选择→实际结果反馈。每个选择呈现不同的行动和取舍；确定性费用明确列出，不确定结果只给方向提示，不伪装成保证收益。
- 选择后先展示结果与真实属性差值，左右人物／家庭面板同步更新，再按用户播放设置继续。卡片保留在年表中，可重新查看选择和后续，不能再次结算奖励。
- 可在合适事件加入场景探索、点击人物查看关系、比较选项、翻看信件／照片等互动；不是所有事件机械复用一种按钮。核心内容与行动不得藏在没有标记的图片热点里，拖动／滑动也必须有按钮和键盘等效操作。
- 普通事件不要求逐条确认；必须决定的事件才暂停。最小化或Escape收起待决策卡后保持待决策状态，显示明确返回入口，不悄悄选默认答案。

### 图片体系与性能

- 按年龄阶段、生活情境、城乡／资源条件和已存在的人物身份匹配图片，保持同一角色的外貌与成长连续性。配图是虚构故事插画，不宣称真实照片；不能用国家标签机械指定唯一族裔外貌。
- 全事件映射要有审计清单：eventId→场景／变体→角色阶段→互动类型→本地化。未知旧事件也有适配卡和合理的场景配图；新事件未配置图片／互动即不通过发布验收。
- 图片采用可复用场景与人物组合，加上重点事件专属素材，避免把同一张客厅图贴满整个人生。全事件有图不等于为每个随机句子即时生成一张新图。
- 不依赖运行时AI生成才能继续游戏。图片按需加载、缓存、固定尺寸；只预取当前卡和紧邻内容。图片失败时保留完整文字、选择和可重试入口，恢复后展示原先确定的图片，不能重新抽事件。
- 文字放在HTML中，不烘焙进图片，便于九语言、缩放和读屏；四主题共享素材体系，卡框、遮罩、文字和按钮遵循各主题颜色。

### 全量交付门槛

1. 先完成日常／人物关系／重大抉择三个端到端原型以验证架构，然后迁移全事件；原型通过不等于全量任务完成。
2. 建立事件清单，全部事件ID的图片映射、互动入口、年龄／人物条件及九语言文案覆盖率均为100%。展示覆盖率和实际加载成功率分别统计，不以默认占位图充当正常素材覆盖。
3. 场景与角色适配、手机触摸／键盘操作、读屏、减弱动效、图片失败、慢网、四主题对比度、重放／旧存档均验收。
4. 待决策在刷新／离开再返回后可恢复；重复点击、连按及高速播放只结算一次，同一时刻只能有一张激活的决策卡。
5. 不把旧数据没有记录的差值显示成“0”或编造因果，应清楚显示未记录，并保留原事件事实。
6. 全事件迁移完成且规则／存档／SEO／真实支付入口回归通过后，才作为本轮完整交付发布。最终验收清单必须列出事件总数、已完成数和未覆盖数，不只展示几张漂亮样例。
